/cmh-ci — explore the PRD/QA landscape, then a guided BNMA, never a hardcoded script

Introduces what's actually in the data first — a complete outcome on its own if that's all you need — and, only when the goal is a full analysis, turns study selection from a silent, hand-edited R vector into a forced, traceable decision at every step — so a low-dose Phase 2 study or a naming mismatch can't quietly skew a competitive-landscape result again.

Model basis
Real production BNMA confirmed against the actual CMH Shiny app

What kept going wrong

!
A silent inclusion skewed a result A low-dose Phase 2 study entered a semaglutide analysis with no one deciding to include it.
!
Naming drift broke scripts A compound-name change silently split one arm into two, unnoticed until the fit looked wrong.
!
No audit trail Study choices lived as a commented-out vector inside a script — not reviewable, not reproducible.
!
The model itself was wrong Hierarchical baseline + the wrong heterogeneity prior — confirmed against the real tool's own source.
